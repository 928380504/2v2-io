# 跑马灯与排行榜跨游戏使用规范

本文定义浏览器游戏模板中跑马灯、排行榜、个人排名窗口和游戏结算桥的稳定契约。它适用于胜局、积分、距离、生存时间、关卡、连击等竞赛模型。新增游戏只能替换指标、事件和文案，不得各自重新发明接口、缓存和交互。

文中“必须”“禁止”“应当”分别对应 MUST、MUST NOT、SHOULD。

## 1. 设计目标

1. 同一套 UI 可以切换不同游戏适配器，不依赖 `wins`、`kills` 等单一游戏字段。
2. 排名由服务端适配器决定，前端只展示，避免浏览器排序产生不一致。
3. 首次访问有内容、失败时保留旧内容、重复访问优先使用缓存。
4. 公共浏览尽量读取共享快照；只有用户主动刷新才请求实时排行。
5. 游戏只上传完成竞赛所需的最小聚合数据，不上传无关玩法内容。

## 2. 固定层与可变层

### 2.1 模板固定层

以下内容跨游戏保持一致：

- `/api/ticker`、`/api/leaderboard/*`、`/api/profile/[profileId]`、`/api/matches/batch` 路径。
- `profile.ready`、`matches.pending`、`matches.ack` iframe 消息流程。
- 日榜、总榜、个人窗口、主动刷新、缓存和错误回退行为。
- 排行榜响应外壳、跑马灯事件外壳、国家代码和时间字段。
- 每批最多 20 个事件、事件幂等、来源窗口与来源域名校验。
- 排行榜顶部、折叠、刷新按钮、尾部刷新说明和移动端响应式顺序。

### 2.2 游戏可变层

每个适配器只能通过配置或后端实现改变：

- `adapterId`、`gameId`、`modeKey`、事件版本。
- 主指标字段、名称、单复数、显示格式和排名方向。
- 平分规则、有效结算条件、里程碑阈值和活动文案。
- 是否支持昨日领奖台、历史奖牌和实时主动刷新。
- 游戏专属统计字段，例如击杀、轮次、单词数或距离。

禁止在通用组件中写死游戏 ID、`wins`、`score`、模式名称或接口地址。

## 3. 竞赛指标配置

站点的 `site/data-provider.ts` 必须为当前适配器声明：

| 配置 | 含义 | 示例 |
| --- | --- | --- |
| `mode` | API 返回的稳定模式键 | `1v1`、`untimed` |
| `metricField` | 排行行中用于展示的主指标 | `wins`、`bestScore` |
| `previousPeriodMetricField` | 上一周期指标 | `previousDayWins` |
| `metricLabel` | 表头短标签 | `WINS`、`SCORE` |
| `metricSingular` / `metricPlural` | 悬停和描述中的单位 | `point` / `points` |
| `previousPeriodLabel` | 上一周期名称 | `yesterday` |
| `activity` | 跑马灯类型、徽章和句式 | `LIVE`、`SCORE` |

服务端必须直接返回最终 `rank`。高值优先、低值优先和复杂平分规则都在适配器中完成，前端禁止根据 `metricField` 再排序。

数字格式由展示适配器决定：普通计数使用本地千分位；距离带单位；持续时间格式化为 `mm:ss` 或 `hh:mm:ss`；不可比较的缺失值显示 `—`，禁止伪装成 `0`。

## 4. 游戏结算事件

### 4.1 消息桥

游戏 iframe 必须发送：

- `profile.ready`：本地档案 ID、昵称和修订号。
- `matches.pending`：尚未确认的结构化结算事件，名称保持兼容，不代表所有游戏都是“比赛”。
- 网站返回 `matches.ack` 后，游戏才能从持久化 outbox 删除对应事件。

父页面必须同时校验 `event.origin` 和 `event.source`，发送时必须使用明确目标域名，禁止使用 `*`。

### 4.2 通用事件约束

每个竞赛事件必须包含：

- `schemaVersion`
- UUID v4 `eventId`
- `eventType`
- `gameId`
- UUID v4 `profileId`
- 玩家昵称
- 稳定模式键
- 发生时间 `occurredAt`
- 游戏版本和本地档案修订号
- 适配器需要的有界数值

同一结算重试必须复用相同 `eventId`。存在“单局”概念时还必须使用稳定 `runId`，数据库对档案与 `runId` 建立唯一约束。客户端时间只用于展示和归属周期，服务端同时记录 `receivedAt` 并拒绝超出允许窗口的时间。

禁止通过截图、OCR、Canvas 像素或不稳定 DOM 文本抓取成绩。只有游戏显式暴露可信状态或加入授权桥接后才能上传。

## 5. 跑马灯数据契约

`GET /api/ticker?limit=20` 的响应必须使用：

```ts
interface CompetitionActivityResponse {
  ok: true;
  day: string;
  generatedAt: number;
  items: Array<{
    eventId: string;
    eventType: string;
    player: string;
    opponent: string | null;
    modeLabel: string | null;
    tier: "live" | "silver" | "green" | "blue" | "purple" | "gold";
    achievementKey: string | null;
    achievementLabel: string | null;
    achievementValue: number | null;
    countryCode: string;
    occurredAt: number;
  }>;
}
```

字段语义：

- `eventId` 必须稳定，用于去重和轮播位置。
- `eventType` 映射为“结果、里程碑、排名变化”三类，不要求所有游戏都有三类。
- `opponent` 可以是对手，也可以是格式化后的主成绩，例如 `12,340 points`。
- `achievementValue` 保存可计算的原始整数，禁止只把数字塞进文案。
- `tier` 只表示视觉等级，不能参与排名计算。

接口返回最近的有效事件，不能把“15 分钟刷新一次”误写成“只查询最近 15 分钟”。当天或短期内事件不足 20 条时允许继续返回更早的最新事件；真正没有数据才返回空数组。

## 6. 跑马灯内容与视觉规范

### 6.1 信息优先级

推荐轮播构成为：

- 结果事件：60%–75%。
- 里程碑事件：20%–30%。
- 排名事件：5%–15%。

某类不足时由结果事件补位。不得直接把数据库最新 20 条原样轮播，导致高频结果永远淹没里程碑和排名。相同玩家、相同事件或同一局的重复消息必须去重。

### 6.2 句式

每条信息只表达一件事：

- 对战：`A defeated B in 1v1 Casual`。
- 积分：`A scored 12,340 points in Untimed`。
- 距离：`A reached 8,420 m in Endless Run`。
- 里程碑：`A reached a 10-win streak — Legendary`。
- 排名：`A entered Daily Top 10 — Elite Challenger`。

内容正文最多使用两种强调色。连接词、模式名和时间使用默认文字色；徽章自身颜色不计入正文色彩数量。禁止给玩家名、对手名、模式名和数值分别使用不同颜色。

### 6.3 布局与交互

- 跑马灯是导航栏下方的全局组件，所有页面共用同一数据和折叠状态。
- 内容宽度必须与当前页面主容器对齐，不能在内页单独写一套左右边距。
- 默认每 15 分钟更新一次；第一次访问没有有效缓存时必须立即请求。
- 展开面板底部显示简短英文更新说明。
- 折叠状态写入带站点命名空间的 `localStorage`。
- 折叠按钮外贴信息容器边缘；无悬停或无操作后约 3 秒隐藏。
- 展开动画遮罩层必须位于按钮上方，避免按钮穿透内容遮罩。
- 缓存读取失败、接口失败或浏览器禁用存储时，组件仍能正常显示本次内存数据。

## 7. 排行榜数据契约

日榜、总榜、个人窗口和实时刷新必须共享以下响应外壳：

```ts
interface LeaderboardResponse {
  ok: true;
  period: "daily" | "allTime";
  mode: string;
  day: string | null;
  resetAt: number | null;
  generatedAt: number;
  dataSource: "snapshot" | "live";
  totalPlayers: number;
  entries: LeaderboardEntry[];
  currentPlayer: LeaderboardEntry | null;
  currentWindow: LeaderboardEntry[];
  lastPlayer: LeaderboardEntry | null;
}
```

每个 `LeaderboardEntry` 至少必须提供：

- `rank`
- `profileId`
- `nickname`
- `countryCode`
- `lastPlayedAt`
- 当前站点配置的 `metricField`

可选能力：

- `previousDayRank` 与上一周期指标，用于昨日领奖台。
- `medals`，用于历史金、银、铜牌累计。
- 游戏专属统计字段，用于个人档案或悬停详情。

不支持的可选能力必须返回 `null`、零值或省略，并由 UI 隐藏；禁止构造虚假奖牌或昨日成绩。

## 8. 排名、分页和个人窗口

- 默认公共榜单最多读取前 100 名，具体上限由站点配置控制。
- 无论用户排名是 5、80、108 还是 1080，前 100 名公共数据都来自相同快照。
- 当前玩家位于前三名时，不额外显示个人窗口。
- 当前玩家位于第 4 名及以后时，显示“上一名、本人、下一名”；即使本人已在前 100 名中也保留个人窗口。
- 当前玩家是最后一名时，个人窗口允许只有上一名和本人。
- 公共榜单与个人窗口之间使用居中的 `•••` 分隔，不重复请求中间所有名次。
- `lastPlayer` 只用于表达榜单总人数或折叠尾部，不得迫使接口返回全部行。

昵称按可用空间渐进截断。响应式隐藏顺序由具体榜单类型声明，但玩家排行的名次、昵称和主指标是不可隐藏的核心信息；国家、次要统计和标签先隐藏。

## 9. 周期、时区和领奖台

- 日榜归属、倒计时、刷新上限、昨日结算和查询参数必须统一使用站点时区配置。
- 禁止一个模块使用 UTC、另一个模块使用浏览器本地时区。
- 日榜 `day` 使用站点时区的 `YYYY-MM-DD`；`resetAt` 是下一次站点日界线时间戳。
- 昨日前三必须在日界线结算一次，并通过唯一日键保证幂等。
- 奖牌累计与日榜结算必须属于同一原子流程，不能依赖晚 15 分钟的独立任务。
- 昨日奖牌悬停展示昨日获奖时的指标，不展示今日指标。
- 不支持领奖台的适配器必须关闭该展示，不能让零值看起来像真实昨日成绩。

## 10. 缓存与刷新

默认基线：

| 数据 | 浏览器/共享缓存 | 主动实时刷新 |
| --- | --- | --- |
| 跑马灯 | 15 分钟 | 不提供独立强刷 |
| 日榜 | 3 小时快照 | 5 分钟冷却，每档案每日最多 12 次 |
| 总榜 | 24 小时快照 | 5 分钟冷却，每档案每日最多 12 次 |
| 个人窗口 | 跟随对应榜单快照 | 主动刷新时一起更新 |

缓存键必须至少包含站点命名空间、适配器/模式、周期、站点日期和缓存结构版本。主动刷新成功后必须覆盖页面状态和浏览器缓存；刷新网页不能退回主动刷新前的旧快照。

首次访问流程：

1. 有可用本地缓存时立即显示。
2. 无缓存时自动请求一次公共快照，禁止等待点击才加载。
3. 缓存过期时先保留旧内容，再后台更新。
4. 请求失败时保留旧数据并显示非阻塞状态，禁止把榜单清空。
5. 只有成功响应且 `totalPlayers = 0` 时才能显示真正空榜状态。

刷新按钮在冷却期间和达到每日上限后必须保持可解释状态。鼠标悬停分别提示剩余冷却时间或 `Daily refresh limit */12`，不能只让按钮失效。

## 11. 性能与数据库

- 公共访问读取预计算统计表或排名快照，禁止每次扫描全部原始事件。
- 个人窗口只查询当前排名附近的 2–3 行，不返回从第一名到本人之间的所有玩家。
- 主动实时刷新才运行实时排名查询；普通首访和页面刷新读取快照。
- 原始事件写入必须幂等；派生统计只处理真正新增的事件。
- 批量接口每次最多 20 个事件，公共卡片和评分继续使用批量读取。
- 新指标先设计必要索引，再上线查询；不能依靠提高刷新间隔掩盖全表扫描。

## 12. 安全、隐私与可信度

- 昵称清理控制字符并限制长度。
- 所有计数、积分、距离和时间必须设置合理整数边界。
- 国家代码来自服务端请求元数据，不信任游戏客户端上报。
- 不保存完整 IP、设备指纹、题库、玩家输入文本或与竞赛无关的数据。
- 客户端成绩默认属于社区娱乐数据，不得宣传为防作弊竞技结果。
- 奖品竞赛必须增加服务器权威状态、签名成绩或可验证回放机制。

## 13. 常见游戏映射

| 游戏模型 | `metricField` | 排名依据 | 跑马灯示例 |
| --- | --- | --- | --- |
| 1v1 对战 | `wins` | 胜局高优先，胜率等平分 | `A defeated B in 1v1 Casual` |
| 文字游戏 | `bestScore` | 单局最高分 | `A scored 12,340 points in Untimed` |
| 跑酷 | `bestDistance` | 单局最远距离 | `A reached 8,420 m in Endless Run` |
| 生存游戏 | `bestSurvivalMs` | 单局最长生存时间 | `A survived 18:42 in Survival` |
| 速通 | `bestTimeMs` | 完成时间低优先 | `A finished Level 5 in 01:48` |

适配器可以改变排序和平分规则，但不得改变响应外壳和通用交互。

内置适配器应通过 `competition-packs/<adapterId>/pack.json` 声明展示指标和
可选迁移，并使用 `competition:install` 启用。安装器只能写站点保护区和
追加迁移，禁止把单站选择写入模板核心或自动连接远程 D1。

## 14. 新适配器验收清单

- [ ] 已声明适配器 ID、游戏 ID、模式键和事件版本。
- [ ] 已定义主指标、单位、格式、排名方向和平分规则。
- [ ] 游戏发送显式结构化结算，不抓取 Canvas 或截图。
- [ ] `eventId` 幂等，单局模型具有唯一 `runId`。
- [ ] 批量上传、档案、跑马灯、日榜、总榜、个人窗口均通过契约测试。
- [ ] 跑马灯不会被高频事件完全占满，正文不超过两种强调色。
- [ ] 首访无缓存时自动加载，失败不清空旧内容。
- [ ] 日榜与总榜使用快照，主动刷新覆盖本地缓存。
- [ ] 时区、日界线、昨日结算和刷新上限调用同一配置。
- [ ] 数据库查询有对应索引，并验证典型流量下的读取行数。
- [ ] 不支持的奖牌、昨日榜或里程碑功能已明确隐藏。
- [ ] 客户端积分的可信边界已在站点说明中披露。
